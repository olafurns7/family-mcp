### [P2] Preserve collection history when feed rows cannot be parsed — packages/infomentor-mcp/src/collection.ts:416

The new per-item filtering counts malformed rows but then treats the reduced feeds as complete input to change detection. This affects the timetable at lines 416–425 and the message/notification paths below it; the existing missing-reference and snapshot code subsequently discards the omitted fingerprints. I reproduced this through actual in-memory MCP calls: establish a quiet baseline, then return the same upstream IDs with one timetable `title`, one message `messageSubject`, and one notification `title` temporarily `null`. Collection succeeds with `skipped: 3`, advances its cursor, emits a shortened timetable as an update, and reports the still-present message and notification as `missing`. Restore the original, byte-identical data and use the returned cursor: all three are emitted as updates again. A scheduler following the documented cursor procedure therefore receives unsupported disappearance/change reports and repeat notifications. Before this delta, malformed rows failed collection without replacing the baseline. Keep partial reads usable, but preserve history for affected feeds or refuse to advance their baseline until complete; add a valid → malformed → unchanged recovery regression. A global `skipped` count does not identify which missing references or timetable changes are untrustworthy.
